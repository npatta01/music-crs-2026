The task

what the challenge asks, and how it is scored

The task

Setup

Every assistant turn

  • Retrieve 20 tracks from a shared 47,071-track catalog
  • Write a short reply presenting the top recommendation

Per-track metadata

Title, artist, album, a median of 17 genre/mood tags, popularity, release date, plus precomputed text, audio, cover-art and collaborative-filtering embeddings.

Splits

Train15,199 sessions (~121.6k turns)
Development1,000 sessions × 8 turns = 8,000
Blind-A / Blind-B80 sessions each, final turns
Blind-B additionally withholds the conversation-goal annotations present in training data.

Built on

TalkPlayData 2. The conversations are LLM-generated, not observed listening sessions — which matters later.

The composite metric

Setup
0.50 · nDCG@20  +  0.10 · cat.div  +  0.10 · lex.div  +  0.30 · (judge − 1)/4

Our Blind-B decomposition

0.50 × nDCG@20 0.25370.1269
0.10 × cat. div. 0.03150.0032
0.10 × lex. div. 0.78620.0786
0.30 × (3.30−1)/40.1725
Composite0.3811

Where the score came from

The judge term out-earned nDCG, and category diversity returned 0.003 of the 0.10 on offer. We optimised almost entirely for relevance and left the diversity terms alone.

State extraction

State extraction

Approach

The extractor

DeepSeek-V4-Flash (build 0423), schema-constrained, given the dialog so far and the IDs of tracks already played.

Deliberately blind

No conversation goals, goal progress, or user profiles reach the extractor. The state is whatever an LLM can read off the conversation.

Why this model

Cheaper extractors under-filled the optional fields — rejections and facets especially — so every final run uses this one. Per-turn extraction is a paid API call, which is what kept us off the training split.

Prompt version

ConversationStateV1, projected to V0Plus for the downstream contract.

Where each field goes

  • The anchor drives the centroid searches
  • The facets become text and audio queries
  • The rejections filter the fused pool

And where they do not

Nothing here becomes a hard filter on album, and the year window never reaches the index. That gap is the main diagnostic later.

This one works

Two hard entities plus a soft facet. The probe flag opens the catalog lookups, the album constrains the pool, and Arcady is genuinely from Grace/Wastelands.

Why it is easy

Everything the listener asked for is a field the catalog actually has. Compare the next failures, where it is not.

State on a request the pipeline cannot use

State
User: “I'm looking for an album with a really striking, abstract cover art. It had some bold colors and shapes, almost like a modern painting.”
Extracted state:
request_type: attribute_search
facet: striking abstract cover art
facet: bold colors and shapes
facet: like a modern painting
routing: image_or_visual_search = true
We served: Frank Ocean — “Pink + White”

Extraction: right

Three visual facets and the image flag — exactly what the schema is for.

Pipeline: nowhere to put it

The flag opens the gated SigLIP-2 cover-art branch, but the reranker has no features for that branch. Whatever it returns cannot be weighed against anything else.
This is the gap in miniature: the state understood the request, and the rest of the pipeline had no way to act on it.

Grounding names to the catalog

Approach

Names → IDs

Fuzzy string matching of artist and track names against the catalog name lists, keeping matches above 80/100. Downstream stages only ever see identifiers.

Free text → tags

  1. Exact match against the tag vocabulary
  2. Alias match
  3. Substring match
  4. Embedding nearest neighbour, cosine ≥ 0.6, top 3
Used by the BM25 branch. Outside it, tag matching falls back to exact strings — part of why so little of the state became executable.

Weighted RRF — baseline and fallback

Approach

Fusion

Weighted reciprocal-rank fusion, k = 60, top-1000 across the branch pools.

Post-fusion adjustments

  • Drop rejected artists and tracks
  • Drop tracks already played
  • Promote / demote on exact tag membership
  • Year-range decay

As a baseline

0.1492
devset nDCG@20, no training

Still the fallback

If the learned ranker is unavailable, this order ships. It is the only part of the ranking stack with no trained component.

Re-ranking

one learned model over the pooled candidates

What the ranker leans on

Approach

Setup

LightGBM LambdaMART, a gradient-boosted tree ranker. LR 0.025, 127 leaves, truncation 200, 5-fold user-grouped CV. ~20.6M candidate rows.

Read it carefully

Split gain describes the fitted model, not recommendation quality. But constraints at 0.7% is real: the ranker leans on similarity, not on what the listener asked for.

Guards after scoring

Exact-track pin when a specific track is named; a final artist-constraint check.

The bi-encoder behind that top feature

Approach

How b1 was trained

Approach
L = −(1/B) Σi log [ exp(vqiᵀ vdi+ / τ) / Σd in Di exp(vqiᵀ vd / τ) ]    τ = 1/20

Positives

53,885
(turn, track) pairs whose next turn's goal-progress says the recommendation moved the session forward

Negatives

4 + batch
four mined hard negatives per positive, plus every in-batch document

Retrieval vs ranking

As a twelfth retrieval branch it added little to the union's coverage and was dropped. As a ranking feature it dominates the fit — out-of-fold nDCG@20 0.1970 → 0.2032.
Not isolated: which parts of the rendering matter, and whether the effect carries to the blind splits.

Down-weighting contradicted turns

Approach

Weight, by what the next turn says

User rejects the labelled track× 0.3
Goal-progress says it did not help× 0.3
User rejects only its artist× 0.6
Floor0.2
Chosen by hand. Never tuned.

The goal-annotation asymmetry

Goal-progress annotations shape training labels — these weights, and the bi-encoder's positives — but are never features. Blind-B removes them, so the deployed ranker is goal-free at inference.

Response generation

Response generation — 30% of the composite

Approach

The deployed style instruction

“Write 1–2 concise sentences about only the selected track. Prioritize the latest user request and extracted state over older conversation history. If the track is reasonably aligned, explain the fit with one specific supported reason. If it clearly conflicts with an explicit avoid/new-artist constraint, do not oversell it or blame the system; briefly frame the limitation and the closest supported reason.”

Setup

Qwen3-30B-A3B-Instruct-2507, temperature 0. One pass over the top-1 track as a delimited XML block (≤10 tags) plus the latest state.

How the prompt was chosen

Eight variants swept over a frozen Blind-A retrieval output → judge 4.70, no recommendations changed. Selected on the leaderboard score.

Missing

No multi-draft sampling, no selection, no checking, no repair pass.

What happened when we used them

A ranker trained on the re-judged labels scored lower — so the submission kept the originals.

The catch

That score is computed against the original labels, so it could not have favoured the relabeling. We release the re-judged labels as evidence to audit, not as a corrected benchmark.

Limits of our own analysis

Analysis
  • The relabeling was never checked against human judgments.
  • The Blind-B quality audit used a single LLM judge.
  • The trace audit was heuristic, not a relevance judgment.
  • The conversations are LLM-generated, not observed listening sessions.
  • Neither blind split exposes relevance labels — blind-set failure rates and relabeling rates are diagnostic, not ground truth.
  • Development-split and leaderboard numbers are separate measurements.

Where it leaves us

what we would change, and what is released

What we would do differently

Conclusion
  1. Hold out a clean split before touching anything. Free, and it would have changed every selection decision we made.
  2. Make the state executable. Rejections and constraints carried 0.7% of model gain — most of what the extractor understood never became a filter.
  3. Import knowledge the catalog lacks — tempo, key, soundtrack and film/TV links — so requests naming them have something to match.
  4. Check the response against the state before emitting it: flag unavailable tracks and unmet constraints instead of overselling a substitute.
  5. Decide what to do when the benchmark and your judgment disagree. We still do not have a principled answer.

Everything is released

Conclusion

Related work — four established lines

A1

Conversational state tracking

CRS systems commonly track dialog state explicitly and condition retrieval on it. We follow that, but compile the state with a prompted LLM instead of a trained tracker.

Retrieve-then-rerank at catalog scale

Pool multiple sources with reciprocal-rank fusion; rank with LambdaMART.

Modality-specific music encoders

Contrastive language-audio pretraining (CLAP), vision-language over cover art (SigLIP-2), collaborative filtering (BPR), general text embeddings (Qwen3).

Our claim

What we report is how that combination behaved — not a new technique.
